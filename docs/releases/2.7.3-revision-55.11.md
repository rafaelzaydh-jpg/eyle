# Eyle 2.7.3 — Revision 55.11

## Cancellation-safe messages and structured reasoning fallback

Revision 55.11 closes two observable failure paths in the web and Agent pipelines.

### Message cancellation

- Removing a message cancels only the job created from that message.
- A different message already frozen inside an active context is deleted after that response finishes, while new jobs exclude it immediately.
- Question jobs use a terminable child process, allowing cancellation to interrupt a blocking local-LLM request.
- Any assistant response produced after cancellation is removed before it can remain in the conversation.

### Structured OpenAI-compatible responses

Some local backends reject `response_format` but still follow the JSON instruction in the prompt. Models with a separate thinking channel may return the complete Agent decision only in `reasoning_content`, leaving `content` empty.

Previously, the compatibility retry called the backend with `forcar_json=False`, which also disabled recovery from `reasoning_content`. The valid decision became an empty response and triggered `agent_llm_empty_response`.

The transport now separates two concerns:

1. whether native `response_format` is sent;
2. whether the original request is structured and may safely recover its JSON from `reasoning_content`.

Therefore the prompt-only fallback can omit unsupported native JSON parameters while still returning the structured decision. Ordinary textual calls continue to ignore `reasoning_content`, preventing private reasoning from becoming user-visible output.

## Regression coverage

- `response_format` rejected twice, followed by `content=""` and JSON only in `reasoning_content`;
- remembered lack of native JSON support on the next structured call;
- ordinary textual response containing only `reasoning_content` remains unusable and private;
- structured streaming remains disabled.
