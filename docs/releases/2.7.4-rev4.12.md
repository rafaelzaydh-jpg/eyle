# 2.7.4 Rev4.12 — Observable execution history

Rev4.12 keeps the Rev4.11.8 agent behavior and adds an objective, expandable runtime history for debugging and token auditing.

## Added

- On-demand `GET /jobs/<id>/history` endpoint.
- **histórico** button on assistant messages associated with a persisted job.
- Expandable sections for agent phase/turns, LLM calls, token accounting, tools and post-write validation.
- Safe tool history with bounded arguments and summarized results.
- Per-call prompt phase/turn metadata.
- Structured write-validation history for apply, `compileall`, tests, tool reread, full reread and rollback.
- `UPDATE_HISTORY.md`, recording recoverable removed designs, why they were removed, and the bar for reintroduction.

## Privacy boundary

The history does not expose chain-of-thought, raw prompts, raw model responses, source contents, evidence hashes or memory bodies. Existing internal-path redaction still applies to the endpoint.

## Performance boundary

History is not included in normal job polling. The browser fetches it only when the user expands the panel, avoiding a new polling/token tax. No LLM call is used to generate or summarize the history.

## Documentation

The GitHub-facing README, Portuguese README, architecture, technical overview and configuration documents were rewritten around the current single-AgentSession/tool-first architecture.

## Validation

- 150 deterministic tests passed in the packaging environment.
- 1 optional Flask interface test was skipped because Flask is not installed there.
- Python `compileall` passes for the release tree.
- Real Qwen behavior remains deployment-only.
