# 2.7.4 Rev4.12.1 — Runtime tools and decision observability

Rev4.12.1 is deliberately incremental. It keeps the Rev4.12 agent loop and adds better deterministic execution tools plus enough public decision metadata to diagnose unnecessary retries.

## What changed

- `calculate` results are now citable runtime evidence. A normal arithmetic request remains LLM-authored and is expected to complete as `LLM → calculate → LLM final` in two calls, including structured finals.
- Public job history now records the observable decision type and outcome for each turn (`tool`, `final`, accepted/rejected) and a bounded deterministic rejection reason such as `FINAL_UNKNOWN_EVIDENCE`. No reasoning or raw model content is exposed.
- `run_tests` is a first-class agent tool during investigation. It executes in the existing sandbox, optionally focuses pytest on one safe file/directory, and returns a bounded diagnostic tail plus concise summary.
- Executed failing tests can be cited as evidence, allowing the Eyle to diagnose a real failure rather than merely reporting that a tool failed.
- `git_status` inspects branch and working-tree changes read-only.
- `git_diff` inspects staged/unstaged changes read-only and truncates diff text before it reaches the model.
- Portuguese/English plural test requests (`testes`/`tests`) now enter project investigation instead of accidental chat mode.

## Design boundary

The runtime still does not author natural answers from utility results. It measures, executes and validates; the LLM remains the voice that explains the result.
