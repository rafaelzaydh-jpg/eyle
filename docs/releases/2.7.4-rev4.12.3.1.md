# 2.7.4 Rev4.12.3.1 — Foundation hardening hotfix

Rev4.12.3.1 is a corrective release built directly on Rev4.12.3. It hardens the audited foundation and, in the final packaged revision, adds `execution_trace` as one sanitized read-only observer over current/persisted execution facts.

## Corrections

- Utility fast paths are now whole-request, narrow matches; arithmetic/self-identity words inside compound project questions no longer hide project tools.
- `run_tests` answer-only optimization closes only requests that are themselves clearly test-only; compound investigations remain open even when the model did not declare a plan.
- Project-evidence gating now covers explicit bug investigations, named-symbol location/use questions, directory state and active-workspace references, while broad architecture opinions/trade-offs remain free reasoning.
- Workspace write detection no longer treats response rewrites such as “corrija sua resposta” or “mude sua explicação, não o código” as code edits; direct code/file mutations remain supervised.
- All tool input arguments now carry model-visible descriptions. `search_code` explicitly performs literal fixed-string search and exposes canonical `query`.
- `memory_store` is labeled `MEMORY_WRITE`, separating external-memory persistence from workspace reads/writes.
- `agent_info` now reports `write_enabled` separately from the invariant that enabled workspace writes require confirmation.
- Observable history records tool requests as requested, then validation as accepted/rejected, then execution as executed/skipped/failed/completed. Rejected tool attempts are retained in tool history.
- Removed an unreachable duplicate `run_tests` history branch.
- Benchmark reports use the active runtime revision instead of a stale Rev4.12 label.
- Worker progress no longer calls the active AgentSession path “routing”.

## Validation

- 183 tests passed.
- 1 optional Flask interface test skipped because Flask is not installed in the packaging environment.
- `python -m compileall` passes.
- Release identity and JavaScript syntax are validated before packaging.

## Intentionally retained compatibility

Legacy `claims[].text` parsing and selected tool argument aliases remain accepted only as protocol compatibility; the active prompt/catalog use sentence-indexed claims and canonical arguments. No legacy reasoning pipeline, semantic router, Scout/Finalizer/MissionSpec path, or automatic project-memory injection is active.

`execution_trace` observes facts only; diagnosis remains the responsibility of the same LLM using normal code/test tools.
