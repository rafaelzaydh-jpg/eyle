# 2.7.4 Rev4.12.4 — Shared tool taxonomy

Rev4.12.4 is built directly on the final Rev4.12.3.1 execution-trace release. It does not add a routing layer or a new reasoning loop. It changes only how model-visible tool capabilities are described so shared authority and side-effect semantics are defined once instead of repeated across every tool.

## Tool taxonomy

Two authority categories are sent once per model call for the tools that are actually available in that runtime phase:

- `READ_ONLY` — may inspect, calculate, execute checks or use temporary validation without intentionally persisting project-file or project-memory changes;
- `EDIT` — may persist project files or project memory; runtime controls still apply.

Effect tags are also shared:

- `NONE` — default, no persistent side effect;
- `EXEC` — executes project code/processes;
- `TEMP` — temporary validation state only;
- `MEMORY_WRITE` — persists external project memory;
- `WORKSPACE_WRITE` — persists project files;
- `VERIFY` — may run post-change verification;
- `ROLLBACK` — may restore changes after failed verification.

Individual tool contracts no longer repeat `side_effects: none`, `does not modify files`, category names, or effect explanations. They carry only purpose, compact argument signatures, returned observation, tool-specific caveats, and configured numeric limits.

## Selection behavior is unchanged

The runtime still filters only actions that are impossible in the current executable phase. The LLM receives all tools allowed in that phase at once and chooses among them. Categories/tags do not select tools, route requests, or add an extra LLM call.

## Wire-size measurement

Using the same serializer and tool set:

- all 20 registered tools: 12,492 characters in Rev4.12.3.1 → about 10,241 characters for taxonomy + contracts in Rev4.12.4;
- normal 15-tool `analysis_investigate`: 8,353 → about 7,049 characters.

The optimization is structural rather than a token-budget workaround; it keeps semantic caveats such as literal-vs-semantic search, token-measurement scope, trace privacy, bounded diff/read output and dry-run/write preconditions.

## Retained execution model

- one `AgentSession` reasoning loop;
- LLM-led tool selection;
- `execution_trace` as the single sanitized self-observability tool;
- supervised writes with dry-run, confirmation, verification and rollback;
- no legacy semantic router, MissionSpec/Scout/Finalizer pipeline or automatic memory prompt injection.
