# Eyle 2.7.3 — Revision 55

## Scope

Revision 55 implements critical optimization phase 2 for local retrieval and project ingestion. It replaces the dense BM25 scan with an inverted index, adds a bounded query-result LRU, and parallelizes safe local ingest work without changing index ordering.

## Inverted BM25 retrieval

`retrieval/buscar.py` now builds postings in the form `term -> [(document_id, frequency), ...]`. Query scoring therefore visits only chunks that contain each query term instead of checking every indexed chunk for every term.

The score formula remains the same as the previous dense implementation. Regression tests compare both implementations and require equivalent scores, including repeated query terms.

Candidate selection now uses an exact max-heap. It pops only as many candidates as needed to satisfy `max_chunks_no_resultado` and the token budget, while retaining the previous behavior of skipping an oversized chunk and trying the next candidate.

## Retrieval query LRU

A thread-safe in-memory LRU stores up to 256 selected retrieval results by default. Its key includes:

- the absolute `chunks.jsonl` path;
- the current index fingerprint (`mtime_ns`, `ctime_ns`, inode where available, size, `k1`, and `b`);
- normalized query tokens, preserving duplicate terms;
- token budget, character/token estimate, and result limit.

Lexically equivalent queries such as different case, punctuation, or token order can reuse the same selection. The cache is invalidated when `chunks.jsonl` changes. Related decisions from `historico.json` are deliberately reloaded on every call so cache hits cannot return stale history.

Default configuration:

```json
{
  "retrieval": {
    "query_cache_ativado": true,
    "query_cache_max_entradas": 256
  }
}
```

## Deterministic parallel ingest

`ingest.py` now uses bounded thread pools for local work that can benefit from I/O overlap and C-backed hashing:

- safe file reads;
- high-confidence secret-content checks;
- SHA-256 manifest hashes;
- Python AST and JS/TS symbol extraction;
- local structure generation;
- chunk creation and chunk hashes.

Directory traversal and `.gitignore` rule evaluation remain deterministic. `executor.map` preserves candidate order, so serial and parallel modes produce the same `estrutura.json`, `chunks.jsonl`, and `index_fingerprint`.

Default configuration:

```json
{
  "ingest": {
    "max_workers": 4,
    "parallel_threshold": 8
  }
}
```

The runtime clamps workers to 32, and the schema rejects invalid values. Small projects remain serial to avoid thread-pool overhead. LLM-based file understanding remains governed separately by the LLM concurrency limiter.

## Validation

- Python compilation passed.
- 218 executable non-web tests passed.
- One Flask-dependent module was skipped because Flask was unavailable in the packaging environment.
- Serial and four-thread ingest outputs were byte-for-byte equal in regression tests.
- Query-cache invalidation, fresh history loading, heap token-budget behavior, and multi-thread execution were covered.
- A synthetic rare-term check with 20,000 documents produced 20 postings, confirming that scoring no longer scans all 20,000 documents. This is an implementation check, not a substitute for benchmarking the final repository and hardware.

## Limits

- BM25 remains lexical and does not understand synonyms like an embedding model.
- Query-cache reuse is limited to lexically equivalent token sets and the same retrieval configuration.
- Parallel ingest gains depend on file count, storage speed, file sizes, Python parsing cost, and whether LLM understanding dominates total ingest time.
