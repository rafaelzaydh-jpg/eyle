# Eyle 2.7.3 — Revision 55.18

**Revision:** `55.18-deterministic-audit-scout-finalizer`  
**Date:** 2026-08-05

Revision 55.18 prevents a capable model from beginning a project audit with an arbitrary convenient file and from planning, investigating, and finalizing inside the same constrained call.

## Deterministic candidate selection

After `list_tree`, Eyle builds a role-based catalog from the preserved inventory:

- entrypoints such as `main.py`, `app.py`, and `index.*`;
- orchestrators such as `engine.py`, `agent.py`, and `worker.py`;
- state and persistence components;
- grounding, recovery, utility, and validation components;
- tests correlated with selected component names;
- principal runtime, dependency, and test configuration.

Documentation is not placed in the source-code candidate catalog. Scout output is normalized against the catalog, invented paths are rejected, and deterministic baseline slots cannot be removed by the model.

## Split audit pipeline

A general project audit now follows this flow:

1. preserve the project inventory;
2. build the deterministic candidate catalog;
3. run an initial Scout that selects valid components and states suspected risks or gaps;
4. execute the initial read queue automatically;
5. run a gap-review Scout with fresh code evidence;
6. execute bounded additional coverage, preferring a related test when available;
7. run a dedicated tool-free Finalizer;
8. apply utility, typed grounding, and minimum-coverage gates before publishing success.

The generic Agent is still used by other task types. It is no longer responsible for choosing tools, controlling the whole plan, interpreting all code, deciding completion, and writing the final project-audit answer in one response.

## Persistence and observability

The audit catalog, selected paths, pending reads, completed reads, failed reads, Scout outputs, phase, and Finalizer call count survive task checkpoints. The public work summary reports the visible pipeline without exposing private reasoning.

## Deliberate boundaries

- Role classification remains deterministic and heuristic; unusual layouts may require new rules.
- The Scout receives at most `agent.audit_candidate_limit` catalog entries, currently 48 by default.
- The default audit reads six initial candidates and one additional gap candidate to remain within the bounded step budget.
- This revision improves investigation coverage and separation of responsibilities; it does not prove universal bug absence.
- The real Qwen 3.8 MAX endpoint was not available in the packaging environment, so model-live validation remains required in the target installation.
