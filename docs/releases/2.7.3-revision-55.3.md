# Eyle 2.7.3 — Revision 55.3

## Problem

The Flask path, queue, Worker, and llama-server were all active, but every generation was cancelled after almost exactly five seconds. The server log showed repeated `cancel task` entries.

The HTTP helper called `urllib.request.urlopen(..., timeout=connect_timeout_seconds)`. With the shipped configuration this was five seconds. `urllib` applies that value not only while opening the TCP connection, but also while waiting for the HTTP status line and response headers. A non-streaming llama-server normally sends those headers only after generation finishes. Therefore any response taking more than five seconds was closed by Eyle, even though `read_timeout_seconds` was 120 seconds.

The later best-effort socket timeout adjustment could not help because it ran only after `urlopen` had already received the headers.

## Fix

- The HTTP operation now uses `read_timeout_seconds` while waiting for a generated response.
- Startup/model discovery remains short because those calls pass the same short timeout as both connection and read limits.
- The default backend URL is now `http://127.0.0.1:8080`, matching the IPv4 address printed by llama-server and avoiding `localhost` resolution ambiguity on Windows.
- A regression test starts a real local OpenAI-compatible HTTP server, delays its response beyond the configured connection timeout, and verifies that Eyle still receives the answer before the read timeout.
