# Eyle 2.7.3 — revision 55.22

## Project-read orchestration and benchmark truth

Revision 55.22 moves the remaining `project_read` path away from the monolithic 512-token agent response. The agent now collects evidence and emits `ready_to_finalize`; a dedicated tool-free Finalizer writes the answer using a separate output budget.

### Provider completion metadata

The response adapter now preserves:

- configured and resolved model;
- `finish_reason`;
- prompt, completion, and reasoning token counts;
- response ID;
- per-call latency and requested output budget.

A provider `finish_reason` such as `length` triggers one bounded retry with a larger output budget. A second truncation fails as `MODEL_OUTPUT_TRUNCATED`; partial text is never published as success.

### Deterministic project-read and edit transitions

- Exact symbol-existence questions with an explicit path use `find_symbol` rather than BM25 `search_code`.
- A missing symbol produces structured negative evidence and an explicit answer.
- After a confirmed patch, the system forces `run_tests`, then a fresh read of the changed range, before allowing finalization.

### Benchmark v2

The benchmark now reports factual correctness, completion, semantic grounding, workflow, and safety as separate dimensions. It records the model actually returned by the provider, every finish reason, actual LLM calls, and per-call latency. Edit scenarios continue through confirmations until a real terminal state or a bounded safety limit.
