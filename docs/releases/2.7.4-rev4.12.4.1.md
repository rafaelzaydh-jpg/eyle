# 2.7.4 Rev4.12.4.1 — Context budget hardening

Rev4.12.4.1 is built directly on Rev4.12.4. It keeps the shared tool taxonomy and `execution_trace`; it changes context capacity and budget policy so ordinary multi-step project investigation can finish without weakening selective retrieval.

## Changes

- default `llm.context_window_tokens`: `10000` → `32768`;
- task-wide `agent.max_prompt_tokens`: `12000` → `96000`;
- total task budget raised to `102000` so the 96k prompt budget can coexist with bounded completions;
- analysis reserve is `llm.agent_analysis_max_tokens` (default `1800`) and no longer scales with source volume;
- patch reserve remains separate for write-producing phases;
- analysis phases never expose `test_patch_dry_run` or `test_patch_set_dry_run`;
- `agent_info` now returns complete `registered_tools` separately from phase-local `available_tools`;
- Windows-style pytest failures remain `TESTS_FAILED` with their real summary/return code;
- `execution_trace` is covered in an integrated investigation that then inspects source with `search_code`.

## Limits

A 32k context window is capacity, not mandatory consumption. Every backend request still performs a full context-window preflight. The 96k prompt value is cumulative across a job; it never permits a single request larger than the configured model context.
