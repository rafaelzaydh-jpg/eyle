# Eyle 2.7.3 — Revision 55.2

## Problem

The browser could show `job #N · completed` while displaying only the user's message. The request had reached Flask, the SQLite queue, and the Worker. The hidden failure happened after that:

1. the local LLM call raised `ErroLLM`;
2. the Engine converted it into a structured result with `status: failed` and intentionally did not save it as assistant conversation content;
3. the Worker ignored the structured status and called `queue.concluir`;
4. `GET /jobs/<id>` hid the result;
5. the browser therefore saw a completed job with no assistant message and no diagnostic.

The default configuration targets an OpenAI-compatible backend at `http://localhost:8080`. If that server is not running, this path is triggered even though Flask on port 5000 is healthy. “No project indexed” does not prevent ordinary chat; an offline LLM backend does.

## Fix

- Structured Engine failures now finalize the queue row as `failed`, not `completed`.
- `queue.falhar` can preserve the structured result alongside the diagnostic.
- `ErroLLM` metadata now carries a stable error code, transient flag, and HTTP status.
- `GET /jobs/<id>` exposes only a redacted user-facing failure message and error code; payload and full result remain private.
- The browser renders a visible failure notice and continues fetching `/conversa` even when `/jobs` polling has a temporary error.
- Deleted message IDs are removed from the browser render cache, preventing a later reused ID from being hidden.
- Startup performs a non-generating backend preflight against `/v1/models` or `/api/tags` and prints a direct warning when the LLM server is unreachable.
- The default provider label now matches the actual OpenAI-compatible backend mode.

## Validation

- `python -m compileall -q .`
- `python -m pytest -q`: 229 passed, 1 Flask-dependent module skipped because Flask was unavailable in the packaging environment.
- `node --check web/static/app.js`
- Regression coverage verifies that a structured Engine failure remains `failed` in SQLite and preserves its safe result.
