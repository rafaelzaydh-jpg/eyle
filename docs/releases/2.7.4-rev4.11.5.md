# Eyle 2.7.4 Rev4.11.5 — Loop and token control

Rev4.11.5 fixes the high-token failure mode where a small write request could spend five or six agent decisions rereading the same project and then end with `MAX_PROMPT_TOKENS_EXCEEDED` or `MAX_LLM_TURNS_EXCEEDED` before producing a patch.

## Changes

- Replaced the universal investigation loop with explicit runtime phases: `write_investigate`, `write_prepare`, `write_patch_only`, `write_patch_retry`, and `analysis_answer_only`.
- Limited normal write investigation to two decisions. The following decision exposes only patch dry-run tools.
- Added semantic read coverage: a whole-file read blocks later ranges of that file, and equivalent tree/search/symbol requests are not executed again.
- Added a two-turn no-progress guard that forces completion from retained evidence or fails clearly instead of spending the remaining budget.
- Kept a compact stable task context across turns so literal constraints do not disappear when full chat history is removed.
- Reduced the fixed agent prompt from about 1,395 conservative tokens to about 371.
- Made tool catalogs phase-specific.
- Added provider cache telemetry for `prompt_tokens_details.cached_tokens` and `input_tokens_details.cached_tokens`.
- Split prompt usage into raw, cached, uncached, and effective totals. Repeated system prefixes use a configurable `cached_prompt_weight` without weakening the per-request context-window check.
- Changed agent tests to use the production aggregate budgets instead of 50k/100k test-only limits.
- Added the exact three-call multi-file regression: list tree, batch-read files, produce one transaction.

Validation: 122 passed, 1 optional Flask test skipped because Flask is not installed in the packaging environment.
