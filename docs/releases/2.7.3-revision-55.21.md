# Eyle 2.7.3 — revision 55.21

## Audit truthfulness hardening

This revision closes inconsistencies found during the final review of revision 55.20.

### Implemented

- Global health claims such as “no critical issues” are rejected even when targeted coverage and a successful test run exist. Only explicitly scoped statements about reviewed components may proceed to grounding.
- Test status is derived from the latest executed `run_tests` action. An older passing run cannot mask a newer failure.
- `project_audit` recovery now returns structured `claims[]` with evidence IDs and never falls back to the legacy `answer + claim_annotations` contract.
- Recovered claims are revalidated against evidence, grounding, health gates, utility, and final coverage.
- English audit routing recognizes requests such as “Analyze the project” and coverage disclosure no longer treats the article “a” as Portuguese.
- Critical-component metrics count only files classified with critical catalog roles; auxiliary files selected by Scout no longer inflate the metric.
- Active technical and benchmark documentation no longer presents revision 53 results as current.
- SQLite connections opened directly by tests are explicitly closed, allowing the suite to run with `ResourceWarning` promoted to an error.

### Validation boundary

The package validation records deterministic tests, Python compilation, JavaScript syntax, release identity, archive integrity, and warning-clean execution. Live Qwen and Flask integration remain external validation tasks because those services/dependencies are not available in the packaging environment.
