# Eyle 2.7.3 — Revision 55.19

**Revision:** `55.19-structured-claims-health-gates`  
**Date:** 2026-08-05

Revision 55.19 moves grounding information into the claims themselves and prevents indexed documentation or old project memory from being promoted into current system-health conclusions.

## Structured claims

The `project_audit` Finalizer no longer returns a free-form `answer` plus a separate `claim_annotations` list. It returns atomic claims:

```json
{
  "final": {
    "claims": [
      {
        "type": "fact",
        "text": "The Worker records failed executions.",
        "evidence_ids": ["ev-0004"],
        "basis": ""
      },
      {
        "type": "risk",
        "text": "This conversion can hide the original failure cause.",
        "evidence_ids": ["ev-0004", "ev-0007"],
        "basis": "The exception is converted into a generic status."
      }
    ],
    "verification": "fresh evidence selected by the audit pipeline",
    "limitations": []
  }
}
```

Eyle validates every claim, derives the legacy grounding annotations internally, unions the referenced evidence IDs, and renders the final response from the validated claim text. A claim containing multiple sentences is rejected so evidence cannot be attached ambiguously to a paragraph.

## Global health gates

Statements such as “there are no critical issues,” “all functionality is operational,” or “the system is production ready” are blocked unless the configured audit coverage threshold is satisfied and current operational proof exists.

Claims that tests pass require a successful `run_tests` action executed in the current task. README files, changelogs, release notes, or indexed summaries cannot prove current test status. Failures are returned as:

- `UNSUPPORTED_HEALTH_CLAIM`
- `TEST_STATUS_NOT_VERIFIED`

The default threshold is controlled by `agent.audit_health_claim_required_score` and is `1.0`.

## Indexed memory trust

`memory/entendimento.json` is rendered before live evidence only as a navigation aid:

- entries without a verifiable current hash are labeled `UNTRUSTED_NAVIGATION_HINT`;
- entries whose persisted file hash matches disk are labeled `HASH_VERIFIED_NAVIGATION_FACT`;
- final project-audit claims still require fresh Evidence Registry IDs.

A hash match proves that the indexed summary refers to the current file version; it does not replace fresh source evidence in the audit conclusion.

## Deliberate boundaries

- Health-claim detection is deterministic and phrase based; it blocks common broad assertions but is not a universal natural-language theorem prover.
- General `project_audit` remains read-only by default, so it normally cannot claim tests are passing unless a future authorized execution phase runs the suite.
- A matching index hash proves freshness of the referenced file, not perfect semantic accuracy of the old generated summary.
- The real Qwen 3.8 MAX endpoint was unavailable during packaging, so live-model validation remains required in the target installation.
