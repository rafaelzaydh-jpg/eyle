# 2.7.4 Rev4.12.2 — Context and test-runner hardening

Rev4.12.2 is a surgical reliability release based on failures observed through the Rev4.12 history panel in a real large workspace.

## Fixed

- Large nested tool results are compacted generically before the next LLM call. `list_tree.entries`, `inspect_project.relation_signals`, test lists and future nested arrays/maps no longer require one hard-coded crop rule per tool.
- Compaction is performed on a deep-copied prompt view. The full result stays in the live `AgentSession` and observable history.
- `run_tests` distinguishes `TEST_RUNNER_UNAVAILABLE` from a suite that actually executed and failed.
- `pytest==8.2.2` is now a runtime dependency because `run_tests` is part of the runtime tool catalog.
- Explicit test requests are guided directly to `run_tests`. After a test observation, non-write analysis moves to answer-only so the model explains instead of wandering through unrelated files.
- Job history distinguishes logical LLM attempts from requests actually sent to the provider and marks local context-budget refusals as `preflight_blocked`.
