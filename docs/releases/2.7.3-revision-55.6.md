# Eyle 2.7.3 — Revision 55.6

## Observed failure

A normal chat request could work while a general project analysis first exhausted the local-LLM retry deadline and later ended with an invalid structured decision. The Agent had two retry layers: transport retries inside each LLM call and a second generation for JSON format repair. On a backend that was briefly unavailable or returned prose instead of protocol JSON, those layers could spend the whole job budget and still publish no useful project answer.

## Changes

- Structured Agent calls now use `llm.agent_retry_max_attempts=1`; chat and textual Executor calls retain the general retry policy.
- If a read-only Agent task fails because of LLM transport/timeout or `invalid_agent_json`, the Engine reclassifies the same request with the legacy read-only router and executes `consulta`, `dicas`, or `visao_geral` without the Agent JSON protocol.
- Edit requests are excluded from this fallback and remain fail-closed.
- The durable Agent checkpoint records the precise fallback cause and pipeline.
- Runtime databases, traces, and stale checkpoints are excluded from the clean ZIP.
