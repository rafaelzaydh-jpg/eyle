# Eyle 2.7.3 — Revision 55.17

**Revision:** `55.17-project-audit-minimum-coverage`  
**Date:** 2026-08-05

Revision 55.17 implements the second P0 correction for shallow project analysis: a general request to analyze a project is now a structured audit, not permission to read one convenient file and stop.

## Implemented

- Added the `project_audit` task type for general project analysis and overview requests.
- Kept explicit single-file questions as `project_read`.
- Added seven deterministic completion criteria:
  1. `inventory_complete`
  2. `entrypoint_read`
  3. `core_logic_read`
  4. `error_paths_read`
  5. `tests_or_test_config_checked`
  6. `coverage_reported`
  7. `grounded_answer`
- Added deterministic path-role classification for entrypoints, core modules, error-handling paths, tests, test configuration, source code, and documentation.
- Forced the next required read from current coverage whenever the model tries to conclude too early.
- Added `SOURCE_CODE_NOT_ANALYZED` when selected audit evidence contains only documentation or no source-code evidence.
- Added `PROJECT_AUDIT_COVERAGE_INCOMPLETE` when structural criteria remain missing.
- Blocked legacy read fallbacks from bypassing audit gates.
- Included minimum coverage in the public work summary.

## Documentation boundary

`README*`, `CHANGELOG*`, `docs/**`, Markdown, reStructuredText, and similar documentation may guide navigation and provide historical context. They never satisfy fresh source-code reading for `project_audit`. A grounded summary of a release note is not accepted as a grounded analysis of the repository.

## Small-project behavior

A repository with multiple source files must read at least two distinct source files so the entrypoint cannot also be the entire core-logic sample by convenience. A true single-source project has an explicit exception: the one source file can satisfy entrypoint and core coverage because no second source file exists. Tests or test configuration are still checked when present, and the public coverage report exposes the scope.

## Deliberate boundaries

- File-role selection is deterministic and heuristic. Unusual layouts may require additional naming rules.
- The audit enforces minimum structural coverage; it does not prove that every bug was found.
- Inventory completeness still depends on the configured tree limits and exclusion rules introduced before this revision.
- Structured claim generation/finalizer work remains outside this P0 release.
