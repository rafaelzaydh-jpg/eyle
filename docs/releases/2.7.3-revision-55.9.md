# Eyle 2.7.3 — Revision 55.9

## Observed failures

During an active job, the browser requested `/jobs/<id>` and `/conversa` every 400 ms, plus `/status`. That produced more than 300 requests per minute for one job while the server allowed 180, so the Eyle panel rate-limited itself with repeated HTTP 429 responses.

When the structured Agent failed and analysis moved to the textual fallback, the general-overview prompt contained only indexed filenames, symbols, and line counts. A one-file project could therefore receive a response saying that the source content was unavailable even though the file existed locally.

## Changes

- Active conversation polling now runs every 1.2 seconds and checks at most two tracked jobs per cycle.
- Job polling rotates when multiple tasks are active, keeping the request budget bounded.
- The browser honors `Retry-After` and applies one shared backoff to jobs, conversation, and status requests.
- Conversation and status polling cannot overlap with themselves.
- A temporary 429 preserves the current online/worker display instead of reporting a false outage.
- Static assets use `Cache-Control: no-cache`, so an old aggressive `app.js` is revalidated after updating.
- General analysis reads fresh real source for projects within configurable limits: 8 files, 600 indexed lines, and 16,000 characters by default.
- The same real-code path is used by the read-only textual fallback after Agent transport/format failure.
- The small-project selection starts from the current safe project tree, preserving secret/path/extension filtering.
