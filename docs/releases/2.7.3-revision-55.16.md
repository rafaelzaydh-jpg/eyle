# Eyle 2.7.3 — Revision 55.16

**Revision:** `55.16-full-project-inventory`  
**Date:** 2026-08-05

Revision 55.16 implements the first P0 correction for shallow project analysis: the full tree returned by `list_tree` no longer disappears inside the 500-character recent-observation summary.

## Implemented

- Added a dedicated structured `project_inventory` to `AgentState`.
- Preserved every entry returned by `list_tree`, including path, type, and depth.
- Persisted the inventory through Agent checkpoints and resumptions.
- Added deterministic inventory metadata: SHA-256 hash, file/directory totals, root entries, extension counts, ignored-item counts, configured limit, depth, filter, and complete/partial coverage.
- Included the full inventory in every subsequent Agent prompt before tool selection.
- Kept compact action logs and recent observations small; the raw tree is not duplicated there.
- Marked truncated inventories as partial and instructed the model not to infer that unlisted files do not exist.

## What this fixes

Previously, `list_tree` could return more than one hundred entries while `AgentState` reduced the result to approximately 500 characters. Central directories such as `engine/`, `llm/`, and `tests/` could disappear before the next model decision. The model then selected documentation or release notes because that was most of what remained visible.

Now the model receives all entries returned by the tree tool. On the packaged repository, 144 entries remained visible in the prompt, including `engine/agent.py`, `llm/executar.py`, and the test suite.

## Deliberate boundary

This revision preserves the complete **returned** inventory. The tree tool still obeys `agent.max_tree_entries`, `agent.max_tree_depth`, filters, `.gitignore`, unsupported-extension rules, and secret protection. When one of those limits makes the result partial, the prompt declares partial coverage. Pagination or hierarchical retrieval for repositories larger than the configured limits remains a later improvement.
