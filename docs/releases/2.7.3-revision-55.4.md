# Eyle 2.7.3 — Revision 55.4

## Problem

After revision 55.3 restored the local-model connection, a general project analysis could still end with `TASK_DEADLINE_EXCEEDED`. The agent used a 300-second shared budget, but every structured decision could wait up to 90 seconds and a read timeout was classified as transient, causing the same full non-streaming generation to be started again.

A general analysis also spent its first LLM call asking the model to choose `list_tree`, even though `GoalState` and the transition validator already required exactly that action. On slow CPU inference, the combination of repeated generations and redundant decisions consumed the full task budget before a grounded final answer was produced.

## Fix

- `GoalState` now drives the mandatory first `list_tree` action directly for every general project analysis. This is a workflow rule, not a small-project shortcut.
- Added `llm.agent_max_tokens` and set it to 512 in the shipped configuration, while normal chat/executor responses retain the larger global ceiling.
- Added `llm.retry_read_timeouts`; the shipped configuration sets it to `false`, so a generation that already consumed its read window is not restarted blindly. Existing external configurations that omit the key retain the previous retry behavior for compatibility.
- Increased `llm.agent_timeout_seconds` to 180 seconds.
- Increased the shared engine/agent deadline to 900 seconds and the worker watchdog to 915 seconds. Individual calls still have their own timeout, so a stalled request does not inherit the entire global deadline.
- Timeout failures now report `READ_TIMEOUT`, separating them from connection refusal/reset errors (`TRANSPORT_ERROR`).

## Consistency

The same state machine remains active for projects of every size:

`GoalState -> mandatory orientation -> agent decision -> tool -> fresh evidence -> grounded final`

Only a transition already made mandatory by the state machine is deterministic. File selection, evidence gathering, analysis, validation, and finalization continue through the agent workflow.
