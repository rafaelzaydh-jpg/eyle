# Eyle 2.7.3 — Revision 54

## Scope

Revision 54 implements critical optimization phase 1 for repeated LLM calls and fixes the token-discovery flow in the browser panel.

## LLM cache

The runtime now checks a bounded in-memory LRU before opening SQLite. Exact responses can therefore be reused during the same process without disk access. On a memory miss, `context/cache_llm.sqlite3` remains the persistent source across sessions.

Default configuration:

- in-memory LRU: 2,048 entries;
- persistent SQLite: 4,096 entries;
- absolute TTL: 24 hours;
- structured agent decisions remain outside the cache;
- empty responses and explicit runtime-error envelopes remain non-cacheable.

The implementation does not use the proposed `@lru_cache` placeholder because a function that always returns `None` cannot be populated safely. The dedicated LRU stores validated responses, is thread-safe, enforces TTL, and remains isolated per cache database and backend fingerprint.

## Token flow

The browser prompt now states that the token can be found in the terminal line printed by `python main.py serve` or, for automatically generated tokens, in `context/web_api_token.txt`. A visible **token** button clears the session value and opens a new attempt without requiring a page reload.

Both supported server entry points now print the token and persistent path. Running `python web/routes.py` directly also starts the Worker, matching the normal `main.py serve` behavior.

## Validation

- Python compilation passed.
- 211 executable non-web tests passed.
- One Flask-dependent module was skipped because Flask was unavailable in the packaging environment.
- JavaScript syntax validation passed with Node.js.
- Added tests for in-memory hits, TTL expiration, LRU eviction, one-backend-call reuse, configuration validation, and token guidance.

## Limits

The cache is exact, not semantic: prompts that differ in content do not share a response. Claimed gains therefore depend on how often the same compiled prompts recur. Real latency and hit-rate gains must be measured with the final local model and workload.
