# Eyle 2.7.3 — Revision 55.5

## Observed failures

Three symptoms appeared in the same session:

1. a successful new chat response was followed by an old `TASK_DEADLINE_EXCEEDED` notice;
2. project analysis paused after a short false cycle;
3. resuming the analysis ended with an invalid structured decision after several retries.

## Root causes

- `worker.max_parallel_jobs=2` allowed two jobs to remain active while `llm.max_concurrent_requests=1` admitted only one model request. An older analysis could therefore remain alive and publish its failure after a newer job completed.
- Browser failure notices were appended to the end of the conversation and did not identify their originating user message.
- Observable-cycle detection accepted only two repeated blocks (`AA` or `ABAB`), which is too little evidence to distinguish a loop from normal orientation.
- The JSON Schema allowed overlapping decision branches and did not require `arguments` for tool calls, while the parser rejected those shapes.
- When a fallback backend emitted a draft decision and then a corrected decision, the parser rejected the entire response as ambiguous.

## Changes

- Effective Worker concurrency is capped by the configured LLM concurrency. With the shipped local backend, jobs are processed in observable order with one consumer.
- `GET /jobs/<id>` exposes only the safe originating message ID and a short text summary; the browser places a failure notice beside that message.
- Cycle detection requires three complete repetitions by default.
- Agent decisions use exclusive `oneOf` branches. A tool branch requires both `tool` and `arguments`.
- Fallback parsing chooses the last structurally valid decision, preserving a model's final self-correction while still rejecting a single envelope containing multiple branches.
- `agent.max_tentativas_parse` is 2, allowing the original generation plus one format-repair attempt.

## Consistency

No project-size shortcut was added. Small and large projects use the same state machine, evidence rules, tool permissions, cycle protection, completion checks, and queue path. Only resource limits and the amount of evidence naturally differ.
