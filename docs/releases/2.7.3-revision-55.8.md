# Eyle 2.7.3 — Revision 55.8

## Observed failure

The local model could complete normal chat but return a valid-looking JSON object with different field names during project analysis. The Agent parser rejected those envelopes. In addition, the read fallback depended on one exact metadata field, so a generic checkpoint adapter could overwrite that field and let the terminal invalid-format message reach the user.

## Changes

- Common unambiguous envelopes (`tool_calls`, `tool_call`, `function`, `action`, `action_input`, `answer`, and related argument aliases) are normalized into the canonical Agent decision format.
- Nested objects inside a canonical `final` envelope are not mistaken for later decisions.
- Read-only fallback detection uses redundant metadata, failure code, and terminal text signals.
- Edit/write tasks remain excluded from automatic textual fallback.
- Short requests such as `Faça a analise` route to project analysis in the Eyle panel.
