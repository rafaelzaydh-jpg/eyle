# Eyle 2.7.4 Rev4.11.7 — Sentence references, Markdown, and directory flow

Rev4.11.7 removes duplicated claim prose from normal structured finals, renders assistant Markdown safely, and fixes folder-related read/write workflows.

## Main changes

- Claims now prefer `{ "sentence": 1, "kind": "fact", "evidence_ids": [...] }`; the runtime resolves that reference to the visible answer sentence for the audit ledger.
- Markdown headings do not count as claim sentences. Legacy `text` claims remain accepted for compatibility.
- The web interface renders `**bold**`, inline code, and fenced code blocks using DOM nodes and text content only.
- Commands such as `traga o HTML`, `embuta`, and `inclua` are recognized as write requests.
- Questions about folders and templates require live project evidence.
- `list_tree` inventories become citable structural evidence instead of a no-progress action.
- Deleting the final file in a directory prunes the empty directory; rollback recreates it and restores the file.

- `compileall` passed for runtime and tests.
