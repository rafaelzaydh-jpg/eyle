# Eyle 2.7.4 Rev4.11.4.2 — Failed-write diagnostics hotfix

Rev4.11.4.2 fixes the case where a confirmed transaction failed its tests, rolled back correctly, but only returned a generic message. A later question such as `Qual foi o erro?` saw the restored files and could incorrectly answer that no error existed.

The runtime now includes the real bounded output from `compileall`, tests, application, or final reread in the failure response. It also stores a structured `write_failure` record with the stage, error code, affected paths, diagnostic output, and rollback confirmation. The next AgentSession promotes that record to citable runtime-validation evidence.

The exact HTML-to-`templates/amor.html` flow is covered with a regression where pytest reports a missing `render_template`; the response exposes that error, the transaction is restored, and the follow-up cites the failed execution instead of the restored code.

Validation: 116 passed, 1 optional Flask test skipped because Flask is not installed in the packaging environment.
