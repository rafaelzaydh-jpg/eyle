# Technical overview — Eyle 2.7.4 Rev4.11.7

Eyle is a single LLM-driven programming agent. One model call can answer directly or request a tool. Tool results return to the same session, but a phase machine closes common write investigation after two turns and reserves the next decision for the transaction.

The core does not pre-classify intent. Greetings, architecture analysis, formulas, unfamiliar functions, and code edits all reach the same agent. Optional planning is a field in the agent decision rather than a separate pipeline.

External memory is available through tools and is never inserted automatically. Workspace discovery is direct; no ingest/index stage exists.

For project analysis, natural prose is accompanied internally by typed claims (`fact`, `bug`, `risk`, or `recommendation`). Claims reference the 1-based order of visible non-heading sentences, avoiding repeated prose. Facts, bugs, and risks must cite evidence generated by real reads, including fresh workspace-tree inventories for structural questions. The runtime also enforces explicit “up to N” limits and retains bounded source snippets.

The web queue, worker isolation, telemetry, and progress reporting are adapters outside the reasoning core.

## Write-failure diagnostics

A failed confirmed transaction reports the actual validation output before ending. The runtime attaches a compact `write_failure` record to the assistant message, including stage, error code, affected files, and rollback confirmation. A follow-up can cite this runtime evidence instead of guessing from the already restored workspace.

## Loop and token control

The fixed agent prompt is about 446 conservative tokens. Tool catalogs are phase-specific. Equivalent reads are rejected from existing evidence, while a compact task anchor preserves literal constraints across turns. Prompt telemetry separates provider-reported total, cached, uncached, and effective tokens; cache discounts never decide whether the agent may keep investigating.

## Interface and directory behavior

Assistant Markdown is rendered with safe DOM nodes for bold and code instead of injecting model HTML. Directory questions trigger live workspace inspection. Directory deletion is represented as a reviewed transaction over contained files, and empty parent directories are pruned after confirmation.
